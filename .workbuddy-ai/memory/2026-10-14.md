# 2026-10-14 — Work log

## "fix the errors" — full suite triage: 4 failures → 0 (all 13 suites green)

Ran the whole puppeteer suite to find the actual errors. Baseline **480 passed /
4 failed**. Two were real defects, two were a test-side race.

### Real bug 1 — dark-mode `--text-muted` failed WCAG AA
`[data-theme="dark"]` (style.css ~118) reused the **light-mode** muted grey
`#64748b`. On the dark section shell `#0a132a` that measures **3.87:1**, below
the 4.5:1 AA floor — and it is used for 0.73–0.76rem metadata (`.rec-row-meta`,
`.rec-section-sub`), i.e. exactly the small text the rule exists to protect.
→ `#9aa8bd` (**7.64:1** on `#0a132a`, **7.48:1** on the composited
`--bg-muted`). The `:root` light value stays `#64748b`; verify with the
composited-contrast method, not a raw hex comparison.

Worth knowing: **every other `--text-muted` consumer is scoped
`html:not([data-theme="dark"])`**, so this token change only affects dark mode.
39 usages total, all inherited the fix.

### Real bug 2 — `dist/` was missing entirely
`npm start` is `node dist/server.js`, but `dist/` did not exist, so
`tests/rental-privacy.test.cjs` died with
`ERR_MODULE_NOT_FOUND: dist/auth/token.js` (it dynamically imports
`dist/auth/token.js` and reads `dist/routes/api.js`). That suite had never run
against this checkout. → `npm run build`, then it passes **74/74**.

Note: the **server on :3000 was already up** (started some other way), so the
suite's HTTP half worked while its `dist` half failed. A stale/absent `dist`
does not announce itself.

### Not a bug — the 2 "collapse to one" failures were a test race
`role-dashboards` resized to 390px, called `applyTheme` + `renderApp`, then
`sleep(400)` and read `.dash-2col`. Measured the real timeline: the element is
**absent for the first ~700ms** and correct from **~900ms**
(`cols=1`, 286px). At 400ms the query returns `null` → `cols: 0` → FAIL.
The app collapses correctly on a fresh mobile load; only the desktop→mobile
resize path is slow because `renderApp()` re-resolves its record lists.
→ Replaced both fixed sleeps with a poll for the element (40 × 100ms + 200ms).

App layout was verified correct all along: `.dash-2col` is
`grid-template-columns: 1fr` at ≤1200px, giving a single 286px column.

### Verified the guard still discriminates
Injected the old bug (`.dash-2col { grid-template-columns: 1fr 1fr; }` in the
≤1200px block) → **47 passed / 2 failed**; restored → **49 passed / 0 failed**.
So the poll did not make the check vacuous.
